                         DATA FLOW - REQUEST LIFECYCLE
═══════════════════════════════════════════════════════════════════════════════

SCENARIO 1: User Login Flow
────────────────────────────────────────────────────────────────────────────

1. CLIENT REQUEST
   │
   │ POST https://api.etelios.com/api/auth/login
   │ Content-Type: application/json
   │ Body: {"email": "user@company.com", "password": "***"}
   │
   ▼

2. NGINX INGRESS (TLS Termination)
   │
   │ • Validates TLS certificate
   │ • Checks rate limit (100 req/min per IP)
   │ • Path match: /api/auth/* → auth-service:3001
   │ • Adds X-Request-ID header
   │
   ▼

3. AUTH-SERVICE POD (Kubernetes)
   │
   │ • Express server receives request
   │ • Validates request body (Joi schema)
   │ • Queries Cosmos DB (auth_db collection: users)
   │ • Validates password (bcrypt compare)
   │ • Generates JWT tokens (access + refresh)
   │ • Caches session in Redis
   │
   ▼

4. RESPONSE TO CLIENT
   │
   │ HTTP 200 OK
   │ {
   │   "success": true,
   │   "data": {
   │     "user": {...},
   │     "accessToken": "eyJhbGciOiJIUzI1NiIs...",
   │     "refreshToken": "eyJhbGci..."
   │   }
   │ }
   │
   ▼

5. CLIENT STORES TOKEN
   │
   │ localStorage.setItem('accessToken', token)
   │

SCENARIO 2: Authenticated Request (Get Employees)
────────────────────────────────────────────────────────────────────────────

1. CLIENT REQUEST
   │
   │ GET https://api.etelios.com/api/hr/employees?page=1&limit=10
   │ Headers:
   │   Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
   │
   ▼

2. NGINX INGRESS
   │
   │ • Path match: /api/hr/* → hr-service:3002
   │ • Forwards Authorization header
   │
   ▼

3. HR-SERVICE POD
   │
   │ • auth.middleware validates JWT (LOCAL validation, no network call)
   │ • rbac.middleware checks user role/permissions
   │ • Queries Cosmos DB (hr-database collection: employees)
   │ • Formats response with pagination
   │
   ▼

4. RESPONSE TO CLIENT
   │
   │ HTTP 200 OK
   │ {
   │   "success": true,
   │   "data": [{employee1}, {employee2}, ...],
   │   "pagination": {page: 1, limit: 10, total: 250}
   │ }
   │
   ▼

5. CLIENT RENDERS DATA


SCENARIO 3: Clock-In (Attendance)
────────────────────────────────────────────────────────────────────────────

1. CLIENT REQUEST
   │
   │ POST https://api.etelios.com/api/attendance/clock-in
   │ Headers: Authorization: Bearer ...
   │ Body: {
   │   latitude: 19.0760,
   │   longitude: 72.8777,
   │   selfie: <file upload>
   │ }
   │
   ▼

2. NGINX INGRESS → attendance-service:3003
   ▼

3. ATTENDANCE-SERVICE POD
   │
   │ • Validates JWT token
   │ • Checks employee status (active)
   │ • Uploads selfie to Cloudinary
   │ • Validates geolocation (within geofence)
   │ • Creates attendance record in Cosmos DB
   │ • Updates attendance summary
   │
   ▼

4. RESPONSE
   │
   │ {
   │   "success": true,
   │   "message": "Clocked in successfully",
   │   "data": {
   │     "attendanceId": "...",
   │     "clockInTime": "2025-12-30T09:00:00Z",
   │     "location": "Mumbai Office"
   │   }
   │ }

                         SECURITY ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════════

AUTHENTICATION & AUTHORIZATION:
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                              │
│  1. JWT Token-Based Authentication                                          │
│     • Tokens issued by auth-service                                         │
│     • Each service validates tokens independently (shared JWT_SECRET)       │
│     • Access token: 15 minutes expiry                                       │
│     • Refresh token: 7 days expiry                                          │
│                                                                              │
│  2. Role-Based Access Control (RBAC)                                        │
│     • Roles: SuperAdmin, Admin, HR, Manager, Employee                      │
│     • Permissions: Granular (e.g., 'attendance:record', 'hr:read')        │
│     • Middleware: requireRole(), requirePermission()                        │
│                                                                              │
│  3. Security Layers:                                                        │
│     Layer 1: TLS/HTTPS (Nginx Ingress)                                     │
│     Layer 2: Rate Limiting (100 req/min per IP)                            │
│     Layer 3: JWT Validation (Each service)                                 │
│     Layer 4: RBAC (Role + Permission checks)                               │
│     Layer 5: Input Validation (Joi schemas)                                │
│     Layer 6: SQL Injection Protection (Mongoose sanitization)              │
│                                                                              │
│  4. Container Security:                                                     │
│     • Non-root user (UID: 1001)                                            │
│     • Read-only root filesystem (where possible)                           │
│     • No privilege escalation                                              │
│     • Capabilities dropped (ALL)                                           │
│                                                                              │
│  5. Secret Management:                                                      │
│     • Azure Key Vault for sensitive data                                    │
│     • Kubernetes Secrets (encrypted at rest)                               │
│     • No hardcoded credentials                                             │
│     • Secrets injected as environment variables                            │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
